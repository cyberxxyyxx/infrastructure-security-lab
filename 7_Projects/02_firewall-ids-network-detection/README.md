# Cybersecurity Lab: OPNsense Firewall & Suricata IDS
Network Scan Detection & Active Directory Monitoring

**Project Type:** Cybersecurity / IDS / Network Security / Threat Detection

[Watch the project demonstration on YouTube.](https://www.youtube.com/watch?v=VnaMIsNCiWA)

## 1. Project Overview

This project demonstrates a network intrusion detection environment using OPNsense Firewall and Suricata IDS.

The main objective is to detect network reconnaissance and Nmap scanning activity originating from a potentially compromised client in VLAN 30 and targeting the Active Directory Domain Controller (DC01).

Suricata uses Emerging Threats (ET) detection rules to inspect network traffic and identify suspicious scanning activity.

## 2. Lab Architecture

| Component | Technology | Purpose |
|---|---|---|
| Firewall | OPNsense | Network segmentation and traffic inspection |
| IDS | Suricata | Network intrusion detection |
| Detection Rules | Emerging Threats (ET) | Identify suspicious network activity |
| Attack Simulation | Kali Linux / Nmap | Generate network scanning traffic |
| Source Host | 10.10.30.100 | Simulated compromised client (VLAN 30) |
| Target | Windows Server / DC01 | Active Directory Domain Controller |
| Virtualization | Proxmox VE | Host the lab infrastructure |

## 3. Implementation

- Configure Suricata IDS on OPNsense.
- Enable and configure Emerging Threats (ET) rules.
- Configure IDS monitoring on the relevant network interface.
- Use Kali Linux to generate Nmap scanning traffic.
- Simulate reconnaissance from 10.10.30.100 (VLAN 30).
- Scan the Active Directory Domain Controller (DC01).
- Monitor network traffic and IDS alerts.
- Analyze detected scanning activity.

## 4. Security Monitoring

The lab focuses on detecting:

- Nmap network scanning activity.
- Port scanning attempts.
- Network reconnaissance.
- Suspicious connection patterns.
- Traffic targeting Active Directory services.
- IDS alerts generated by Suricata and ET rules.
