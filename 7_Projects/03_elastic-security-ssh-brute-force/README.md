## 1. Project Overview

This project demonstrates a security monitoring and intrusion detection environment using Elastic Security SIEM.

The main objective is to detect SSH brute-force attacks targeting an Ubuntu Linux Web Server. Kali Linux is used to simulate repeated failed SSH authentication attempts.

Linux authentication logs are collected and forwarded to Elastic Security using Filebeat or Elastic Agent, allowing suspicious authentication activity to be monitored, analyzed, and detected.

## 2. Lab Architecture

| **Component** | **Technology** | **Purpose** |
|---|---|---|
| SIEM | Elastic Security | Security monitoring and threat detection |
| Log Management | Elasticsearch / Kibana | Log storage, search and analysis |
| Attack Simulation | Kali Linux | Generate SSH authentication attempts |
| Target Server | Ubuntu Linux Web Server | SSH authentication and log generation |
| Log Collection | Filebeat / Elastic Agent | Collect and forward authentication logs |
| Response | Fail2ban / Firewall | Mitigate suspicious SSH activity |
| Virtualization | Proxmox VE | Host the lab infrastructure |

## 3. Implementation

- Configure SSH service on the Ubuntu Linux Web Server.
- Enable and verify Linux authentication logging.
- Install and configure Filebeat or Elastic Agent.
- Forward authentication logs to Elastic Security.
- Verify incoming authentication events in Kibana.
- Use Kali Linux to simulate SSH brute-force attempts.
- Configure detection rules for repeated failed SSH logins.
- Monitor authentication activity and generated security alerts.
- Investigate suspicious source IP addresses.
- Implement response actions using Fail2ban or firewall rules.

## 4. Security Monitoring

The lab focuses on detecting:

- Repeated failed SSH authentication attempts.
- Multiple login attempts from the same source IP.
- Suspicious authentication patterns.
- Unauthorized SSH access attempts.
- Successful authentication following repeated failures.
- Security alerts generated by Elastic Security.
